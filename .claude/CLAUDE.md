# Project Instructions

## General Principles

- Understand before implementing.
- Follow existing repository conventions.
- Prefer composition over modification.
- Keep changes minimal and reviewable.
- Avoid introducing new abstractions unless necessary.

## Implementation Rules

- Do not modify public API models unless explicitly requested.
- Do not introduce schema or database changes.
- Avoid changing existing routing algorithms.
- Keep implementation isolated.
- Prefer one new module over modifying multiple existing files.

## Coding Standards

- Match existing naming conventions.
- Follow existing logging patterns.
- Avoid unnecessary comments.
- Do not generate placeholder code.

## Workflow

Before implementation:

1. Explain the plan.
2. Identify affected files.
3. Wait for approval.

After implementation:

- Explain design decisions.
- Highlight trade-offs.
- Suggest follow-up improvements separately from the implementation.
